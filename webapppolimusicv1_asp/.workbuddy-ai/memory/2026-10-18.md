## Corrección post-despliegue (500 en login.asp)

El usuario publicó la app en `C:\inetpub\wwwroot\webapppolimusicv1_asp` y recibió un 500
genérico a la altura de los primeros iconos. **Causa**: `Icon(name, cls)` se declaró con dos
parámetros pero se invocaba con uno (`Icon("home")`) → "Wrong number of arguments" en
VBScript. Diagnóstico confirmado pidiendo la página por HTTP: la respuesta se cortaba
justo en `<%= Icon("waveform") %>`.

**Solución aplicada**: dos funciones explícitas — `Icon(name)` y `IconC(name, cls)` — para
no depender de `Optional` (que en VBScript no admite valores por defecto). Se actualizaron
las 8 llamadas de dos argumentos en `songs.asp`, `default.asp`, `album_detail.asp` y
`playlist_detail.asp`.

Además: token CSRF ahora es solo dígitos (`Csrf()`), `Response.Buffer` en `api_play.asp`,
y herramientas nuevas `deploy/check_calls.py` (aridad de todas las llamadas; detecta
exactamente este bug: 95 avisos con el fallo, 0 con la corrección), `deploy/smoke_test.py`
(login + recorrido de las 15 páginas por HTTP) y `deploy/update.bat` (recopia a la
subcarpeta publicada sin tocar la configuración de IIS, `-SkipIisConfig`).

**Lección**: en VBScript toda función debe invocarse con el número exacto de argumentos;
no hay parámetros opcionales con valor por defecto. Ejecutar `check_calls.py` antes de
cada despliegue.

## Segundo y tercer fallo (login no redirigía / 500 al enviar el formulario)

**A) `Request` devuelve objetos `IStringList`.** En este IIS, `Request.QueryString("x")`,
`Request.ServerVariables("x")` y `Request.Form("x")` devuelven un objeto (VarType 8 pero
`IsObject=True`, `TypeName=IStringList`), no un String. El guard `ElseIf IsObject(v) Then
Txt = ""` de `Txt()` descartaba TODOS esos valores → `IsPost()` siempre False y
`IsLoggedIn()` siempre False. **Solución**: `Txt()` ya no descarta objetos; convierte con
`CStr` y, si falla, con `v & ""`, devolviendo "" solo si ambas fallan. Verificado con
`diagnostico.asp` (página de diagnóstico, restringida a localhost).

**B) ADO: `rs.Open cmd, cn, ...` con un Command que ya tiene ActiveConnection.**
Error real: *"No se puede cambiar la propiedad ActiveConnection de un objeto Recordset que
tiene el objeto Command como origen"* (800a0bb9 / 1240656). Reproducido desde Python con
pywin32 contra el SQL Server real. **Solución**: fijar `CursorLocation/CursorType/LockType`
como propiedades y llamar `rs.Open cmd` sin el segundo argumento. Verificado: devuelve el
usuario y `RecordCount` funciona.

También se hizo tolerante a objetos `ToInt`, `FmtNum`, `FmtDate`, `FmtDateTime`, `IsoDate`
(antes `IsNumeric`/`IsDate` sobre un `IStringList` daban False y perdían el valor, p. ej.
todos los `?id=`), y se sustituyeron los `IsNull(campo)` por `Txt(campo) = ""`.

Herramientas añadidas: `deploy/smoke_test.py` (login + 15 páginas por HTTP),
`diagnostico.asp`, `deploy/check_calls.py`. Método de trabajo que funcionó: reproducir el
ADO con pywin32 y leer el estado real de `Request` con una página de diagnóstico.

## Cuarto fallo: `IconC` devolvía a la función equivocada

Tras corregir ADO, el smoke test dio 13/17 páginas OK y 500 en `default.asp`, `songs.asp`,
`album_detail.asp` y `playlist_detail.asp`: todas las que pintan botones de reproducción.
La salida se cortaba justo en `<%= IconC("play", "ico-play") %>`.

Causa: al dividir `Icon` en dos funciones, `IconC` quedó así:

```vbscript
Function IconC(ByVal name, ByVal cls)
    Icon = IconHtml(name, cls)   ' ← asignaba a Icon, no a IconC
End Function
```

VBScript no permite asignar al nombre de otro procedimiento desde dentro de una función →
error en tiempo de ejecución. Corregido a `IconC = IconHtml(name, cls)`.

**Chequeo nuevo** en `deploy/check_calls.py`: detecta funciones que asignan su resultado a
otro nombre de función (ignorando variables locales declaradas con `Dim`, para no marcar
falsos positivos como `icon = "check"` en `RenderFlash`). Ahora: 0 aridad, 0 retorno mal
asignado, 0 hallazgos estructurales en 28 archivos.

## Estado final: aplicación funcionando

`deploy/smoke_test.py` → **15/15** páginas OK. `deploy/functional_test.py` → **31/31**
(roles admin/usuario, 5 reproductores, columna Actions solo para admin, bloqueo de
`users.asp`/`song_form.asp`/`user_form.asp` al listener, 9 assets). Reproducción real con
Playwright: al pulsar play la barra muestra el título, el badge "Playing" y la fila queda
marcada; `api_play` responde `{"ok":true,"id":1,"plays":1}`.

**Bug visual encontrado en las capturas reales**: los SVG en línea sin tamaño explícito se
renderizaban a tamaño por defecto (el candado del login salía de ~200 px). Solución: regla
base `svg { width: 1em; height: 1em; flex: 0 0 auto; vertical-align: -0.125em }` en el
reset, más `white-space: nowrap` en `.panel__title`.

**Limpieza**: se borró la canción de prueba `__t` (ID 8) que dejó una prueba COM y se
restauraron los contadores `PLAYS` a 0..4. La BDD queda como el seed original.

Lección de método: cuando el ASP no da traza, (1) leer el estado real con una página de
diagnóstico, (2) reproducir ADO/COM con pywin32, (3) capturar la UI real con Playwright.
Los tres encontraron bugs que los chequeos estáticos no podían ver.
